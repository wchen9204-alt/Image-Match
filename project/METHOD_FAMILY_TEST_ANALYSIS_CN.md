补充两点现状：
- `batch_keypoint.yaml` 当前指向的是 `orb_pipeline.yaml`，所以点特征法现在应先看 ORB 批结果，不再以旧的 SIFT 批结果作为主结论。
- 图像指标里的 `PSNR / SSIM / RMSE` 已经从当前评测配置移除，后面不再把它们作为主判断依据。旧输出里如果还看到这些列，说明那是历史结果。

今天已经做过的一项修正也先记在这里：
- `raw / filtered / inliers` 的定义和使用已经重新理顺，不再像之前那样容易混在一起看。
- 现在应按下面理解：
  - `raw`：matcher 直接产出的原始匹配。
  - `filtered`：经过 filter 阶段后的匹配。
  - `inliers`：几何估计阶段判定为满足当前模型的内点。
- 这次修正的意义是：后面再看可视化、日志、summary 时，至少这三个层次的语义已经比之前清楚，不再把“过滤后的匹配”和“几何内点”混为一类。

整体印象：

逐个先记：

- `Test02`：成功，`13` 个内点，`IoU=0.482095`，结果可用但重叠不算高。

- `Test04`：失败，原因是 `inliers 3 < 4`。这类失败是匹配质量阈值挡下来的，不是几何直接崩掉。
- `Test05`：失败，原因是 `failed to refine rigid transform from RANSAC inliers`。这类失败更像是进入几何后，内点支撑不够稳定，或者 partial affine 到 rigid 的压回失败。

- `Test09`：当前成功，`33` 个内点，`IoU=0.681109`。这类局部重叠样本现在是可以接受的，不应再用整图类指标轻易判失败。

当前最值得记住的几点：
- `num_raw_matches` 和 `num_filtered_matches` 现在很多样本完全一样，这至少说明“当前 matcher + filter 组合并没有明显缩掉候选”。这里还要继续查，到底是过滤确实没起作用，还是当前输入本身已经是单路匹配结果，导致过滤空间很小。
- `Test04` 和 `Test05` 代表了两类不同问题：
  - `Test04`：几何前还有匹配，但过不了 `match_quality` 阈值。
  - `Test05`：RANSAC 有初步结果，但 rigid 精修失败。
- `Test06` 和 `Test09` 要分开看：
  - `Test09` 属于局部重叠场景，成功是合理的。
  - `Test06` 目前更像是假阳性风险样本，后面要靠可视化继续确认。
- `Test04`、`Test06` 还要额外注意一种 `180` 度旋转歧义：
  - 如果两张图真实关系里带有 `180` 度旋转，而图像纹理在旋转 `180` 度后又几乎不变，那么一张图的左边和另一张图的右边就可能被错当成可直接对应的区域。
  - 这时即使没有恢复出正确旋转，warp 也可能只靠平移就让局部区域看起来发生了重合。
  - `Test06` 这种大面积近似全灰、纹理弱的样本尤其容易出现这种情况；`Test04` 也要按这个方向一起排查。
  - 所以后面看这两个样本时，不能只看“有没有重合”，还要看“是不是在正确旋转方向上重合”。 

### 过滤方法现状

当前工程里已经实现并实际尝试过的点特征过滤方法主要有：
- `ratio_test`
- `cross_check`
- `distance_distribution`
- `distance_threshold`
- `min_distance`
- `gms`

现阶段可以先记一个明确结论：**还没有找到合适的过滤方法**。

这里说“不合适”，不是指这些方法完全不能运行，而是指它们目前都没有稳定解决当前点特征法的问题。已经看到的现象大致是：
- `MATCH` 直接匹配在一些样本上反而比 `KNN + ratio_test` 更稳。
- 一旦切到 `KNN`，很多样本虽然候选数变了，但最终几何结果并没有明显变好。
- 有些过滤方法筛完之后，`filtered_matches` 仍然和 `raw_matches` 很接近，说明它们没有有效压掉坏匹配。
- 也有一些方法会把候选压得太狠，导致后面 RANSAC / rigid 阶段可用内点更少。
- `gms` 这类更强调空间一致性的过滤，当前实现虽然已接入，但暂时也没有表现出稳定优于现配置的效果。

所以目前对过滤这一块的判断应该是：
- 现有过滤器里，还没有哪个能作为“默认推荐方案”写死。
- 现在的瓶颈仍然是“错配压不干净”和“压完之后有效对应又不够多”这两个矛盾同时存在。
- 后面还需要继续找更合适的过滤方法，不能认为这个问题已经解决。

另外还要记住：即使后面找到了更强的过滤方法，它也未必能单独解决 `Test04`、`Test06` 这类样本。因为这两个样本的问题不只是“坏匹配太多”，还可能包含“`180` 度旋转歧义下，错误方向的局部重合也能骗过当前流程”。

### 历史参考：SIFT

`project/outputs/batch/keypoint/sift_pipeline/summary.csv` 仍然有参考价值，但现在只能作为旧批次记录，不应再拿它代表当前主线结果。

SIFT 这条线上之前已经确认过几件事：
- `Test01/04/05/06` 的主要失败点都集中在 rigid 阶段，典型报错是 `failed to refine rigid transform from RANSAC inliers`。
- 之前调过 `MATCH`、`KNN`、`ratio_test`、`cross_check` 后，能确认 filter 不是完全没执行，但对这些坏样本的改善有限。
- 问题核心更像是：进入几何的候选里仍然有较多错配，或者当前对应关系更支持带统一缩放的 similarity / partial affine，而不是严格 rigid。

所以现在对 SIFT 的判断先保留为：
- 不是单纯 norm 配置问题。
- 不是单纯 filter 没跑。
- 主要还是匹配质量和 rigid 约束之间不匹配。
